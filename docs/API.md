# API AgroConnect MVP

Этот файл — **краткая карта основных сценариев**, а не вручную поддерживаемая полная спецификация всех endpoint'ов.

Канонический контракт текущего backend генерируется самим FastAPI:

- Swagger UI: `http://localhost:8000/docs`;
- ReDoc: `http://localhost:8000/redoc`;
- OpenAPI JSON: `http://localhost:8000/openapi.json`.

Если этот документ и Swagger расходятся, актуальным считается OpenAPI текущей версии backend.

## Служебные страницы

- `GET /api/health` — проверка доступности backend;
- `/internal/dashboard` — внутренняя страница метрик и продуктовых событий;
- `/internal/metrics` — backend-only представление внутренних метрик.

В хакатонном MVP внутренние endpoint'ы не являются production-защищённой административной системой.

## Особенность MVP: тестовый пользователь

Полноценной регистрации и аутентификации в MVP нет. Текущий пользователь передаётся как `user_id` / `viewer_id`:

- в query-параметре;
- в path/body — в зависимости от endpoint'а.

Это сознательное упрощение хакатонной версии. В production `user_id` должен определяться сервером из authenticated principal/access token, а не приниматься от клиента как источник доверия.

## Основные группы API

### Пользователи и поля

- получение списка тестовых пользователей и профиля;
- редактирование профиля;
- поля пользователя;
- создание поля;
- контуры/география;
- единый режим доступа ко всем полям хозяйства;
- история севооборота.

### Лента

- локальная лента;
- публикации;
- реакции;
- комментарии;
- личные записи «Только для меня».

### Соседи

Ключевые сценарии:

```text
GET    /api/neighbors
GET    /api/nearby-farmers
POST   /api/neighbors/{neighbor_user_id}
DELETE /api/neighbors/{neighbor_user_id}
GET    /api/neighbors/{neighbor_user_id}/fields
```

«Хозяйства рядом» и явная связь «Сосед» — разные механики. Добавленный сосед может оставаться релевантным независимо от географического расстояния.

### Доступ к полям

Запрос создаётся для пары «владелец хозяйства — сосед» и относится ко всем полям владельца, а не к одному конкретному полю.

После одобрения сосед получает доступ к текущим и будущим полям этого хозяйства в рамках выбранной модели MVP.

### Предупреждения и пасеки

API поддерживает:

- пасеки;
- общие alerts;
- погодные предупреждения;
- предупреждения об обработках;
- получателей alert по географическому сценарию.

### Погода

Погодный API AgroConnect скрывает внешние источники от frontend.

Клиент обращается только к backend AgroConnect, а backend:

- получает прогноз через выбранный weather provider;
- использует фактические данные ближайшей метеостанции компании, если она подходит;
- нормализует результат для web/Android клиента;
- создаёт погодные предупреждения по продуктовым правилам.

Синхронизация списка метеостанций компании выполняется служебным endpoint'ом после настройки `COMPANY_API_*`.

### ML / plant health

Основные сценарии:

- получить список доступных ML-провайдеров;
- выполнить анализ фотографии;
- сохранить `accepted / rejected / corrected` feedback;
- связать анализ с публикацией;
- после подтверждения пользователя создать предупреждение соседям;
- получить внутреннюю выборку размеченных примеров.

Подробности: [ML_PLANT_HEALTH.md](ML_PLANT_HEALTH.md).

### Product analytics / monetization

Backend принимает продуктовые события и хранит метрики экспериментов. Monetization в MVP является тестом интереса: платежей, реальной подписки и рекламной сети нет.

## Формат ошибок

Ошибки FastAPI обычно имеют формат:

```json
{
  "detail": "Human-readable explanation"
}
```

Типичные статусы:

- `400/422` — некорректные данные;
- `403` — действие недоступно пользователю;
- `404` — сущность не найдена;
- `409` — конфликт состояния;
- `5xx` — серверная/внешняя ошибка.

Для точных request/response schema и актуального списка endpoint'ов используйте Swagger/OpenAPI текущего backend.
