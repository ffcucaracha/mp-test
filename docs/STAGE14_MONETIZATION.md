# Этап 14. Гипотеза-приманка и платный отказ от рекламы

## Цель

Этап 14 не реализует полноценную монетизацию. Он проверяет две продуктовые гипотезы до разработки дорогих функций и платежной инфраструктуры.

1. Пользователи готовы проявлять интерес к расширенным профессиональным функциям.
2. Часть пользователей готова платить за отсутствие рекламы после того, как столкнулась с рекламной вставкой в продукте.

Все действия считаются **псевдоплатными экспериментами**: реального списания денег, подписки и рекламного кабинета в MVP нет.

---

## Эксперимент A. Premium teaser

В ленте показывается карточка:

> Расширенная аналитика хозяйства
> Сравнение сезонов, рисков и эффективности полей.

Кнопка выглядит как доступ к будущей функции, но после клика пользователь получает понятное сообщение, что функция находится в разработке.

Логируются события:

```text
premium_teaser_shown
premium_teaser_clicked
```

Основная метрика:

```text
teaser CTR = premium_teaser_clicked / premium_teaser_shown
```

Это не считается покупкой. Эксперимент проверяет только интерес к будущему premium-value proposition.

---

## Эксперимент B. Реклама → платный отказ от рекламы

### Сценарий

После заданного времени использования ленты **или** после заданного количества пользовательских активностей показывается тестовая реклама сеялки.

Триггер выбирается по принципу «что наступит раньше»:

```text
VITE_AD_DELAY_MS
или
VITE_AD_ACTIVITY_THRESHOLD
```

Значения по умолчанию:

```text
VITE_AD_DELAY_MS=120000
VITE_AD_ACTIVITY_THRESHOLD=6
```

Для короткой демонстрации на хакатоне значения можно уменьшить, например:

```bash
VITE_AD_DELAY_MS=15000 VITE_AD_ACTIVITY_THRESHOLD=3 npm run dev
```

В одной пользовательской сессии реклама показывается не более одного раза. Для этого используется `sessionStorage`.

### Рекламный креатив

Используется тестовая карточка:

```text
Сеялка «АгроСев 4.2»
Точный высев, контроль секций и стабильная глубина.
```

Это демонстрационный креатив внутри MVP, а не реальная рекламная интеграция.

Карточка занимает приблизительно четверть высоты экрана и закрывается крестиком.

События:

```text
ad_impression
ad_closed
```

В `ad_impression.properties` сохраняются:

```text
campaign
trigger = time | activity
activity_count
elapsed_ms
```

## Offer после закрытия рекламы

После закрытия рекламы сразу показывается предложение:

> AgroConnect Plus
> Убрать рекламу за 299 ₽/мес

Пользователь выбирает:

```text
Подключить без рекламы
Не сейчас
```

Под кнопками явно указано:

> Это тест платежного интереса: списаний и реального подключения в MVP нет.

Таким образом эксперимент измеряет willingness-to-pay без обмана пользователя и без подключения платежного провайдера.

События:

```text
ad_free_offer_shown
ad_free_offer_accepted
ad_free_offer_declined
```

В properties сохраняются:

```text
plan = agroconnect_plus_ad_free
price_rub_month = 299
source = ad_close
```

## Backend API

### Запись события

```text
POST /api/experiments/monetization/events
```

Пример:

```json
{
  "user_id": 1,
  "event_name": "ad_free_offer_accepted",
  "properties": {
    "plan": "agroconnect_plus_ad_free",
    "price_rub_month": 299,
    "source": "ad_close"
  }
}
```

Backend принимает только события из whitelist этапа 14, чтобы произвольные клиентские event names не загрязняли продуктовую аналитику.

### Агрегированные метрики

```text
GET /api/experiments/monetization/metrics
```

Ответ содержит:

```text
counts
teaser_ctr_percent
ad_close_rate_percent
offer_decision_rate_percent
ad_free_acceptance_percent
```

`ad_free_acceptance_percent` считается только среди пользователей, которые уже приняли решение:

```text
accepted / (accepted + declined)
```

## Product events

Полный список событий этапа:

```text
premium_teaser_shown
premium_teaser_clicked
ad_impression
ad_closed
ad_free_offer_shown
ad_free_offer_accepted
ad_free_offer_declined
```

Они сохраняются в общей таблице `product_events`, поэтому автоматически попадают и в существующий внутренний event log AgroConnect.

## Как интерпретировать результаты

### Premium teaser

Если CTR высокий, это сигнал продолжать discovery по расширенной аналитике. Это ещё не доказательство готовности платить.

### Ad-free offer

Сильнее всего интересует воронка:

```text
ad_impression
→ ad_closed
→ ad_free_offer_shown
→ accepted / declined
```

Главная продуктовая метрика:

```text
ad_free_acceptance_percent
```

Для хакатона значения на нескольких тестовых пользователях не являются статистически значимыми. Их задача — показать, что гипотеза сформулирована, измеряется и технически готова к реальному эксперименту.

---

## Что намеренно не реализовано

В MVP не добавляются:

- реальные рекламные сети;
- таргетинг;
- частотные рекламные аукционы;
- платежный провайдер;
- настоящая подписка;
- скрытие рекламы после тестового acceptance;
- биллинг и чеки;
- автоматическое продление.

Это отдельный production scope после подтверждения гипотезы.

---

## Критерий завершения этапа 14

Этап считается завершённым, если можно показать сценарий:

```text
пользователь работает с лентой
→ по времени или активности появляется реклама сеялки
→ пользователь закрывает рекламу
→ получает предложение AgroConnect Plus без рекламы
→ принимает или отклоняет
→ решение появляется в product events и monetization metrics
```

Дополнительно должен работать premium teaser «Расширенная аналитика хозяйства» с отдельным CTR.
