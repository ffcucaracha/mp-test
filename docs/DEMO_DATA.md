# Demo / seed data AgroConnect MVP

Демо-данные собраны как связанные пользовательские истории, а не как случайный набор записей. Они нужны для стабильной демонстрации MVP и проверки ключевых сценариев.

## Важно: seed выполняется только на пустой базе

Если PostgreSQL уже содержит пользователей, `seed_data()` повторно данные не создаст.

Для чистого локального reset:

```bash
docker compose down -v
docker compose up -d --build
```

`docker compose down -v` удаляет локальный PostgreSQL volume и все созданные в нём данные.

## Поля

В seed **57 полей**:

- 52 реальных контура из предоставленного для хакатона KML;
- 5 дополнительных demo-полей для Омской области.

Для KML-полей сохраняются названия, культуры 2026 года, контуры, центры и рассчитанные площади. Поля распределены между владельцами географическими кластерами.

У пользователя действует единый режим доступа ко всем его полям:

- `A` — детали открыты;
- `B` — подробные данные доступны после одобрения запроса от соседа.

При необходимости KML seed можно пересобрать:

```bash
cd backend
PYTHONPATH=. python scripts/generate_seed_fields.py /path/to/03-09-2026_fields.kml
```

## Публикации

Seed содержит связанные публикации по основным статусам MVP:

```text
sowing      — посев
sprouts     — всходы
flowering   — цветение
problem     — проблема
harvest     — урожай
treatment   — обработка
```

Есть реакции `🌾 +1` / `🥀 -1` и комментарии.

Ключевые demo-публикации:

- Анна — проблема на пшенице;
- Анна — цветение рапса;
- Ильдар — рапс после дождя;
- Лейсан — проблема на участке пара;
- Сергей — посев кормовой кукурузы;
- Ильдар — плановая обработка;
- Ольга — цветение рапса рядом с пасекой.

## Соседи и доступ к полям

В seed заранее подготовлена сеть между Анной, Ильдаром и Ольгой.

Есть оба состояния запроса доступа:

- `pending`: Ильдар запрашивает доступ ко всем полям Анны;
- `approved`: Анна имеет одобренный доступ ко всем полям Ильдара.

Это позволяет показывать механику приватности без ручной подготовки базы.

## Пасеки и предупреждения

В seed есть две пасеки:

- пасека Ольги в татарстанском кластере;
- «Любинская пасека» Алексея в Омской области.

### Pesticide alert

Ильдар создаёт событие о плановой обработке. Пасека Ольги попадает в радиус события, поэтому Ольга получает предупреждение. В комментарии к публикации она подтверждает получение информации.

### Weather alert

У Анны есть demo weather alert о риске заморозка на одном из её полей.

Реальная погода в приложении при этом запрашивается отдельно через погодный backend-сценарий; seed alert нужен как устойчивый демонстрационный пример.

## Что seed сознательно не подменяет

- не создаёт fake feedback для ML: подтверждение/исправление лучше выполнить живьём;
- не создаёт monetization events заранее;
- не подменяет реальный погодный API;
- не является production-данными пользователей.

## Короткий demo-flow

1. Войти как **Анна Иванова**.
2. Показать ленту, поле и историю севооборота.
3. Показать погоду и offline-сценарий «Поехал в поля».
4. Открыть «Соседи» и показать различие между явными соседями и хозяйствами рядом.
5. Переключиться на **Ольгу Лебедеву** и показать предупреждение об обработке рядом с пасекой.
6. Вернуться к проблемной публикации Анны и показать human-in-the-loop ML.
7. При необходимости завершить внутренним dashboard с метриками.
