# Демонстрационное видео AgroConnect MVP

## Цель и формат

Видео должно доказать, что это работающее мобильное приложение, а не набор экранов. Как и в демонстрации проекта «ИТ в нефтяной отрасли», лучше показать один связный путь пользователя, а не перечислять функции.

- Длительность: **2:40–3:20**.
- Формат: запись экрана + спокойная озвучка после записи + короткие подписи к важным моментам.
- Кадр: **вертикальный 9:16**, 1080×1920 или 720×1280.
- Темп: действия выполнять чуть медленнее обычного; загрузки и ожидание AI ускорить на монтаже.
- Музыка не нужна: голос и звуки интерфейса важнее.

Главная мысль ролика: AgroConnect соединяет личный рабочий дневник поля, помощь соседей и полевые сценарии, которые не ломаются при плохой связи.

## Рекомендуемый способ записи

### Основной вариант: Android-эмулятор или телефон

Это лучший вариант: в кадре сразу видно, что MVP действительно работает как Android-приложение.

Перед записью собери APK с публичным backend:

```bash
cd frontend
VITE_API_URL=http://195.19.209.119:8000 npm run build
npx cap sync android
```

В Android Studio запусти приложение на эмуляторе. Для чистого кадра:

1. выбери портретную ориентацию;
2. увеличь размер эмулятора до 100 %;
3. закрой Android Studio поверх эмулятора и браузер;
4. отключи системные уведомления и не показывай панель разработчика;
5. включи `Show taps` в Developer options, только если кружки нажатий выглядят аккуратно.

Для записи можно использовать встроенный рекордер Android Emulator: кнопку с тремя точками → **Record and Playback** → **Record screen**. Он сохраняет чистое видео устройства без рамок Android Studio.

На физическом Samsung S23 можно использовать системную «Запись экрана». Это даёт наиболее убедительный результат, но перед записью включи режим «Не беспокоить» и отключи всплывающие уведомления. Голос лучше записать отдельно на ноутбуке и наложить после.

### Резервный вариант: веб-версия в мобильном кадре

Если Android-версия на момент записи нестабильна, запиши веб-версию. Это допустимо, если оставить только содержимое мобильного окна без адресной строки, панели браузера и рабочего стола.

1. Открой `http://195.19.209.119:5173` или локальный frontend.
2. В Chrome нажми `F12`, затем `Ctrl+Shift+M`.
3. Выбери портретное устройство около **390×844** и масштаб 100 %.
4. Записывай только область страницы через OBS Studio: Window Capture → Crop/Pad или Display Capture → обрезка рамкой.
5. Экспортируй в 1080×1920, добавив при необходимости однотонные поля сверху и снизу.

Не записывай браузерную адресную строку: она превращает мобильный ролик в скринкаст сайта.

## Автоматическая запись через Selenium

В репозитории есть воспроизводимый путь:

- `demo/test_demo_video.py` — Selenium-сценарий с демонстрационными паузами;
- `scripts/record-web-demo.sh` — поднимает отдельный виртуальный экран, запускает тест и пишет MP4 через `ffmpeg`;
- `demo/assets/plant-problem.svg` — локальное фото для сценария AI и офлайн-публикации.

Один раз установи системные зависимости Ubuntu:

```bash
sudo apt update
sudo apt install -y xvfb ffmpeg
```

Chrome у тебя уже используется для веб-версии. Скрипту достаточно, чтобы команда `google-chrome`, `chromium` или `chromium-browser` была доступна в `PATH`.

Установи Python-зависимости отдельно от backend:

```bash
python3 -m venv .venv-demo
source .venv-demo/bin/activate
python3 -m pip install -r demo/requirements.txt
```

Backend и frontend должны быть подняты заранее. Для локальной записи:

```bash
docker compose up -d --build
./scripts/record-web-demo.sh
```

Для записи с публичного сервера:

```bash
DEMO_BASE_URL=http://195.19.209.119:5173 \
./scripts/record-web-demo.sh
```

Результат появится в `demo/output/` и не попадёт в Git. Скрипт записывает чистый кадр 450×1000, а затем сам накладывает русские субтитры. Рядом остаётся `.srt`-файл с теми же временными метками: его можно отредактировать или добавить в видеоредактор вместо прожжённого варианта. После записи наложи голос и, при необходимости, обрежь первые/последние полсекунды.

Тест намеренно меняет только демонстрационные данные: ищет соседа, создаёт одну офлайн-публикацию и запускает AI-анализ. Перед чистовой записью используй свежую demo-базу. Если внешний AI-провайдер не отвечает, ролик не падает: Selenium оставляет на экране сам AI-сценарий.

## Данные и подготовка

Для полного сюжета сбрось базу и загрузи demo seed заранее:

```bash
docker compose down -v
docker compose up -d --build
```

На сервере вместо reset используй уже подготовленную демонстрационную базу. Перед записью открой приложение онлайн как минимум один раз под Анной: это прогреет офлайн-кэш полей, ленты, погоды и карты.

Основные персонажи:

- **Анна Иванова** — основная демонстрация полей, севооборота, ленты и погоды;
- **Илья Соколов** — растениевод, планирующий обработку;
- **Ольга Лебедева** — растениевод и пчеловод, получающий предупреждение.

Если в старом seed пока отображается фамилия «Морозова», используй фактическое имя на экране, но перед финальной записью обнови сервер до версии с сидером Ивановой.

## Монтаж

1. Сначала запиши экран целиком без голоса. Ошибочные дубли не удаляй во время записи, просто начни действие заново после паузы.
2. Обрежь паузы, загрузки и переходы. В AI-сценарии допустимо ускорение до 1,5–2×.
3. Запиши озвучку отдельно в тихой комнате. Речь должна быть короче, чем действия в кадре: не нужно читать каждый пункт интерфейса.
4. Добавь только 5–6 кратких титров: «Дневник и севооборот», «Метеостанции компании», «Офлайн-очередь», «Предупреждение пасечнику», «AI с подтверждением человека», «Метрики пилота».
5. Экспорт: H.264 MP4, 1080×1920, 30 fps. Если ролик показывают на большом экране, сделай дополнительно горизонтальный 16:9 монтаж из той же записи с телефоном по центру и короткими подписями сбоку.

## Предпоказный чек-лист

- Backend отвечает: `curl http://195.19.209.119:8000/api/health`.
- В приложении нет старого интерфейса: перед съёмкой собрать frontend и выполнить `npx cap sync android`.
- Все три demo-пользователя открываются.
- У Анны видны поле, севооборот и погода.
- У Ольги есть предупреждение об обработке.
- Офлайн-запись реально появляется в очереди и после `navigator.onLine === true` отправляется кнопкой «Отправить сейчас».
- В браузере открывается `http://195.19.209.119:8000/internal/dashboard`.
- В кадре нет логов, DevTools, паролей, API-ключей и уведомлений.

## Что показать, если сценарий на съёмке даёт сбой

- **Нет связи с API:** не пытаться чинить во время записи. Перейти на заранее записанный Android-клип или на веб-версию с тем же сценарием.
- **AI ждёт внешний провайдер:** показать подготовленный результат в Demo · offline и пояснить, что пользователь подтверждает подсказку.
- **Погода не пришла:** показать последнюю сохранённую карточку с видимым временем обновления и источником. Не выдавать старые данные за текущие.
- **Нет времени на монетизацию:** оставить один кадр тизера и один кадр дашборда. Это достаточно, чтобы объяснить измеряемый эксперимент.
