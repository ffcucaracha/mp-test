# Stage 17 — Offline field mode

## Цель

Ключевой сценарий AgroConnect происходит не в офисе, а непосредственно на поле, где мобильный интернет может быть слабым или отсутствовать. Поэтому приложение не должно терять фото, координаты и запись пользователя только из-за недоступного backend.

Этап 17 делает MVP **offline-tolerant**: приложение остаётся доступным, показывает ранее загруженные рабочие данные, позволяет зафиксировать публикацию с поля и отправляет её после восстановления связи.

Это не полноценная distributed/offline-first система с разрешением всех конфликтов. Для хакатона приоритет — сохранить критичный полевой сценарий.

## Что работает без сети

После хотя бы одного успешного онлайн-запуска:

- приложение открывается: web assets находятся внутри Android APK;
- сохраняется выбранный пользователь;
- ранее загруженные GET-данные читаются из IndexedDB;
- доступны сохранённые профиль, поля, лента, соседи, предупреждения и другие уже открывавшиеся данные;
- GPS/геолокация работает независимо от мобильного интернета, если Android может получить координаты;
- камера и галерея работают;
- пользователь может создать публикацию с поля с фото, статусом, текстом и координатами;
- такая публикация попадает в локальный outbox и не теряется при закрытии страницы;
- приложение показывает число действий, ожидающих отправки;
- при появлении сети outbox синхронизируется автоматически;
- можно запустить повторную синхронизацию вручную;
- последний актуальный прогноз погоды доступен офлайн;
- уже просмотренные тайлы карты сохраняются service worker и могут отображаться повторно без сети.

Первый запуск/первый вход без ранее созданного локального кэша по-прежнему требует интернет.

## Архитектура локального хранения

`frontend/src/offline.ts` использует IndexedDB `agroconnect-offline`.

### Store `cache`

```text
key
value
cached_at
```

Успешные GET-ответы API сохраняются под ключом `api:<path>`. Если сетевой запрос позже не проходит, клиент возвращает последнюю сохранённую версию.

Это stale-cache fallback: онлайн-данные всегда приоритетны, локальная копия используется при сетевой ошибке.

### Store `outbox`

```text
id
path
method
body
label
created_at
attempts
last_error
```

Для полевой публикации в `body` сохраняются в том числе уменьшенное JPEG-изображение в Data URL и координаты. IndexedDB выбран вместо `localStorage`/Capacitor Preferences, потому что размер фото заметно больше обычных key-value настроек.

## Синхронизация публикаций

Сценарий:

```text
пользователь фотографирует растение
        ↓
выбирает поле + статус + текст
        ↓
нет сети
        ↓
POST payload сохраняется в IndexedDB outbox
        ↓
"Сохранено на устройстве"
        ↓
появляется сеть
        ↓
syncOutbox()
        ↓
POST /api/posts
        ↓
успешный элемент удаляется из outbox
        ↓
лента обновляется
```

Триггеры синхронизации:

- browser event `online`;
- периодическая проверка раз в минуту, пока приложение открыто;
- кнопка «Отправить сейчас».

Если backend отвечает 5xx или сеть снова пропадает, отправка останавливается и запись остаётся в очереди. Для 4xx запись сохраняется с `last_error`, чтобы данные не исчезли молча.

### Ограничение фоновой синхронизации

Текущая версия синхронизирует outbox, когда приложение запущено. Для production-версии на Android следующий шаг — WorkManager/Capacitor background task, чтобы отправка выполнялась и после сворачивания приложения.

## Погода

`WeatherPanel` использует отдельный локальный cache key для каждого пользователя и поля.

Политика:

- прогноз запрашивается у backend/Open-Meteo только при наличии сети;
- soft TTL: **3 часа** — после этого при сети выполняется обновление;
- прогноз дополнительно обновляется при событии `online`;
- пока прогноз моложе **72 часов**, он может показываться офлайн;
- UI показывает возраст данных (`Офлайн-кэш: N ч назад`);
- старше 72 часов прогноз считается нерелевантным и пользователю показывается явное сообщение об устаревании;
- ручное обновление отключено без сети.

Важно: старый прогноз не маскируется под текущий. Время последнего обновления является частью интерфейса.

## Карта

Старый `iframe` OpenStreetMap заменён на контролируемую приложением сетку стандартных OSM tiles вокруг координаты поля.

`vite-plugin-pwa / Workbox` использует `CacheFirst` для:

```text
https://tile.openstreetmap.org/{z}/{x}/{y}.png
```

Политика кэша:

- сохраняются **только фактически просмотренные тайлы**;
- до 180 элементов;
- срок хранения до 30 дней;
- attribution `© OpenStreetMap` остаётся видимым.

Мы намеренно не делаем массовое скачивание регионов с публичного OSM tile server. Для реального продукта полноценная офлайн-карта должна перейти на собственный источник/PMTiles/MapLibre либо другого провайдера с условиями использования, разрешающими offline packs.

## ML без сети

Текущие Kindwise и Gemini требуют сети. Реализация PlantVillage использует ONNX без внешнего API, но inference сейчас выполняется **на backend**, поэтому отсутствие связи телефона с backend всё равно блокирует анализ.

Для настоящего offline ML следующий архитектурный шаг:

```text
PlantVillage/собственная модель
        ↓
ONNX/TFLite
        ↓
onnxruntime-mobile / TFLite в Android
        ↓
Capacitor native plugin
        ↓
предсказание непосредственно на телефоне
```

Альтернатива для небольших моделей — ONNX Runtime Web/WASM в web layer. Это сделает базовую диагностику полностью независимой от сети.

## Что ещё имеет смысл перенести в offline-first

### Высокий приоритет

1. **Севооборот и полевые заметки** — очередь `crop-season`/field diary mutations; это естественно создавать непосредственно на поле.
2. **Комментарии и реакции** — optimistic UI + outbox. Конфликтный риск небольшой.
3. **Создание поля офлайн** — client UUID, затем server ID reconciliation после sync.
4. **Фото/черновики отдельно от публикаций** — список «Не отправлено», редактирование и удаление до синхронизации.
5. **Плановая обработка пестицидами** — сохранить предупреждение локально и обязательно отправить при восстановлении сети, показывая, что пока оно ещё не доставлено пчеловодам.
6. **Offline ML на устройстве** — особенно полезен именно в полевом сценарии.

### Средний приоритет

7. Заранее загружать перед выездом: свои поля, последние предупреждения, погоду и тайлы вокруг собственных полей.
8. Локальный поиск/фильтрация по кэшированной ленте и истории поля.
9. Локальные Android notifications по уже загруженному прогнозу, например о заморозке ближайшей ночью.
10. Кэшировать thumbnails фотографий ленты отдельно с ограничением места.

### Production hardening

11. Версионирование сущностей (`updated_at`/ETag) и стратегия конфликтов.
12. Idempotency key/client operation UUID для каждого outbox item, чтобы повторная отправка после сетевого обрыва не создала дубль.
13. Android WorkManager/background sync.
14. Ограничение хранилища и LRU-cleanup больших изображений.
15. Шифрование чувствительных локальных данных и очистка cache при logout, если это потребуется моделью угроз.
16. Полноценные offline map packs из источника, который разрешает такое использование.

## Текущая граница MVP

Stage 17 гарантирует наиболее важное: **фермер может зафиксировать наблюдение с фотографией и координатами в поле без интернета и не потерять запись**. Погода и уже просмотренная карта остаются полезными в пределах своего срока актуальности, а ранее загруженные данные доступны для чтения.

Операции, требующие немедленного взаимодействия с другими пользователями (новые предупреждения, запросы доступа, онлайн-ML), по-прежнему должны явно показывать, что доставка/анализ произойдут только после появления связи.
