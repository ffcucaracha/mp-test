# AgroConnect MVP — offline field mode

## Цель

AgroConnect рассчитан на работу непосредственно в поле, где мобильный интернет может быть нестабильным или отсутствовать. Поэтому критичный сценарий не должен зависеть от постоянной связи с backend.

Текущая версия — **offline-tolerant MVP**: приложение показывает ранее загруженные данные, сохраняет изменяющие действия локально и отправляет их после восстановления сети.

Это не полноценная распределённая offline-first система с разрешением всех конфликтов, но основной полевой сценарий уже работает.

## Что доступно без сети

После хотя бы одного успешного онлайн-запуска:

- Android-приложение открывается из локальных web assets внутри APK;
- ранее загруженные GET-данные читаются из IndexedDB;
- доступны сохранённые профиль, поля, лента, соседи и предупреждения;
- GPS может работать без мобильного интернета;
- камера и галерея доступны;
- пользователь может создать публикацию с фото, статусом, текстом и координатами;
- поддерживаются другие изменяющие действия через outbox;
- последний актуальный прогноз погоды доступен офлайн;
- ранее подготовленные/просмотренные тайлы карты могут использоваться повторно.

Первый запуск без локального кэша по-прежнему требует доступ к backend.

## Локальное хранение

`frontend/src/offline.ts` использует IndexedDB `agroconnect-offline`.

### Cache

```text
key
value
cached_at
```

Успешные GET-ответы сохраняются локально. При сетевой ошибке клиент может использовать последнюю сохранённую версию.

### Outbox

```text
client_id
path
method
body
label
kind
priority
created_at
attempts
last_error
```

Поддерживаемые типы очереди:

- `post`;
- `reaction`;
- `comment`;
- `crop_season`;
- `field_create`;
- `pesticide_alert`;
- `generic`.

Каждая операция имеет `client_id`; при отправке он передаётся как `X-AgroConnect-Operation`. Это основа для безопасной повторной отправки и дедупликации.

## Синхронизация

Типовой сценарий:

```text
пользователь выполняет действие
        ↓
сеть недоступна
        ↓
операция сохраняется в IndexedDB outbox
        ↓
интерфейс показывает, что действие ждёт отправки
        ↓
сеть появляется
        ↓
очередь отправляется на backend
        ↓
успешная операция удаляется из outbox
```

Пользователь также может запустить синхронизацию вручную.

Если backend отвечает временной ошибкой (`5xx`, `408`, `429`) или сеть снова пропадает, операция остаётся в очереди. Ошибка сохраняется в `last_error`.

## Android WorkManager

В Android-сборке outbox дополнительно зеркалируется через native bridge.

`frontend/scripts/patch-android-workmanager.mjs` добавляет в генерируемый Capacitor-проект native-компоненты, необходимые для фоновой отправки очереди через Android WorkManager.

Поэтому Android может продолжать работу с накопленной очередью не только через открытый React/WebView-сеанс.

Важно: этот patch устанавливается командой:

```bash
npm run cap:sync
```

Для Android не следует заменять её обычной парой `npm run build && npx cap sync android`, потому что тогда native bridge не будет гарантированно установлен.

## Создание поля офлайн

Для локально созданного поля используется временная запись в отдельном store `local-fields` и `local_ref`. После успешной синхронизации временный объект удаляется и дальше используется серверная сущность.

## Погода

`WeatherPanel` хранит отдельный cache key для каждого пользователя и поля.

Политика актуальности:

- прогноз запрашивается только при наличии сети;
- если сохранённые данные старше **3 часов**, при наличии сети выполняется обновление;
- при событии `online` прогноз проверяется повторно;
- прогноз моложе **72 часов** можно показывать офлайн;
- UI показывает возраст данных;
- данные старше 72 часов считаются устаревшими.

Прогноз запрашивается на 72 часа и в интерфейсе агрегируется в прогноз на 3 дня.

## Режим «Поехал в поля»

Перед выездом пользователь может заранее подготовить рабочий набор данных.

`prepareFieldTrip()` сохраняет:

- профиль;
- ленту;
- соседей;
- предупреждения;
- запросы доступа;
- поля;
- севооборот по полям;
- погоду по каждому полю;
- тайлы карты вокруг полей на используемых масштабах.

Ошибка одного погодного источника или отдельного tile не отменяет подготовку остальных данных.

## Карта

Для PWA `vite-plugin-pwa / Workbox` использует `CacheFirst` для тайлов OpenStreetMap с ограничением по количеству и сроку хранения.

В сценарии «Поехал в поля» тайлы дополнительно сохраняются вручную в Cache API (`osm-field-tiles`).

Массовая загрузка больших регионов с публичного OSM tile server намеренно не реализована. Для реального продукта офлайн-карты лучше строить на собственном/разрешённом источнике, например MapLibre + PMTiles или другом провайдере с поддержкой offline packs.

## ML без сети

`Kindwise` и `Gemini` требуют интернет.

`PlantVillage` использует локальную ONNX-модель, но inference в текущем MVP выполняется на backend. Поэтому отсутствие связи телефона с backend всё равно блокирует этот вариант анализа.

Полностью автономный ML на телефоне — следующая итерация:

```text
ONNX / TFLite model
        ↓
onnxruntime-mobile / TFLite
        ↓
Capacitor native plugin
        ↓
предсказание на устройстве
```

## Граница MVP и production-hardening

Уже реализовано:

- stale-cache fallback для чтения;
- outbox для основных полевых действий;
- offline-создание поля;
- ручная и автоматическая синхронизация;
- Android WorkManager bridge;
- подготовка поездки;
- локальная погода и тайлы карты.

Для production потребуются дополнительные меры:

- формальная стратегия разрешения конфликтов версий;
- серверная идемпотентность для всех mutating endpoint'ов;
- лимиты и LRU-cleanup локального хранилища;
- шифрование чувствительных локальных данных;
- полноценные offline map packs из подходящего источника;
- telemetry для фоновой синхронизации и ошибок WorkManager.
